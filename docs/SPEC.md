# Youth Group — описание продукта

Живой документ: сюда записываются все принятые решения. Если решение меняется — правим здесь.

## Зачем

Держать связь молодёжной группы в одном месте, без замусоренных чатов: духовные материалы, общение, события, фото — всё в одном приложении.

## Формат

- **Мобильное приложение для App Store и Google Play** (решено сразу идти в магазины).
- **Язык интерфейса — только английский** (все кнопки, надписи, уведомления). Люди пишут сообщения на любом языке.
- **Тон текстов — простой разговорный английский, по-молодёжному.** Коротко, тепло, как друг пишет другу: «I'm in», «Ask anything», «No one will know it's you». Без заумных и канцелярских формулировок, но и без перегибов — никакого натужного сленга и мемных словечек.
- Один код на iPhone и Android: **Expo (React Native)**, сборка в облаке через EAS (Mac для сборки не обязателен).
- Пока разрабатываем — смотрим через Expo Go на телефоне, симулятор iPhone на Mac или браузерную версию.
- **Свой собственный стиль.** Ни в коем случае не копировать стиль других проектов владельца (сайт, приложение по деньгам, бизнес-приложение). Всё отдельно.
- Аккаунт разработчика Apple / Google и на кого он оформляется — решим позже, сейчас делаем продукт.
- **Безопасные отступы — обязательны на каждом экране.** Сверху у телефона полоса с камерой и «шторкой» — туда нельзя ставить текст, заголовки и кнопки. Снизу — отступ из-за скругления экрана и системной полоски. Фон (например, градиент) может заходить под эти зоны, содержимое — нет. В браузерном предпросмотре эти зоны нарисованы (чёрный вырез сверху, полоска снизу), чтобы было видно как на настоящем телефоне.

## Роли

| Роль | Кто | Как получить |
|---|---|---|
| Участник | любой | обычная регистрация (sign up), без одобрения |
| Лидер | лидеры группы | **назначает главный лидер (админ)**; сам себя назначить нельзя |
| Админ (главный лидер) | пастор / главный лидер | задаётся вручную при запуске |

Регистрация (решено 2026-11-19): **только имя и email**. Вход — по **одноразовому коду из письма**, без пароля.
- Телефон не собираем вообще. Паролей нет — значит, и красть нечего.
- Email нужен только чтобы прислать код и узнать человека при следующем входе. В приложении его не видит никто — ни участники, ни лидеры; в наши таблицы он не копируется.
- День рождения — **по желанию**, только день и месяц, без года (допущение, ждёт подтверждения владельца).

## Безопасность данных — требование №1

Никто не должен иметь возможности украсть данные зарегистрированных людей. Правила:
- **Собираем минимум:** имя, email для входа, по желанию день и месяц рождения. Больше ничего.
- **Защита стоит в самой базе**, а не в приложении: каждая таблица закрыта по умолчанию, доступ открывается точечными правилами (RLS). Приложению не доверяем.
- Участник видит у других только имя и роль. День рождения другого человека напрямую прочитать нельзя — только готовые списки «сегодня» (всем) и «ближайшие» (лидерам).
- Секретный ключ базы никогда не попадает в приложение — в телефоне только публичный ключ.
- На каждое правило есть автоматический тест «чужой не может прочитать / изменить» (`npm run test:db`). Новая таблица без правил и тестов не добавляется.
- **Регистрация открытая, без одобрения** (решено владельцем 2026-11-19): люди регистрируются сами, лидер никого не одобряет. Это значит, что любой, кто скачал приложение и подтвердил email, видит имена, чат и события. Защита от случайных людей — жалобы, блокировка и удаление участника главным лидером. Переключатель одобрения в базе есть, но выключен и в приложении не используется.
- **Приложение скрывается из поиска App Store** (решено владельцем 2026-11-20): подана заявка Apple на режим «Unlisted App» — приложение не видно в поиске, категориях и списках, открывается только по прямой ссылке (она не меняется) или по QR-коду с этой ссылкой. Группа делится ссылкой между своими. Условие Apple: вернуть приложение в общий поиск потом нельзя — владелец согласился. Это не защита: по ссылке приложение откроет кто угодно. Вход по коду группы и одобрение лидером предлагались и владельцем отклонены («пока ограничимся скрытием из поиска»). Посторонний, если войдёт, видит имена, общий чат, события с местом и временем и альбомы; email и личных сообщений нет.
- Ожидаемый размер группы — около 300 человек (со слов владельца, 2026-11-20).
- **Участник появляется в группе только после подтверждения почты** (исправлено 2026-11-20, применено к живой базе): раньше строка в Members создавалась сразу после ввода адреса, ещё до кода из письма. Так в списке появился «New member» — проверяющий Apple опечатался в служебном адресе (`rview@…`), запрос пришёл из сети Apple, входа не было. Теперь профиль создаётся в момент, когда код введён верно (`supabase/migrations/20261120000011_confirmed_members.sql`, тест «an address joins the group only after its email is confirmed»). Система входа по-прежнему хранит у себя адреса, которым отправляла код, — в приложении их не видно.

## Функции для всех

### 1. Ежедневное слово (из воскресной проповеди)
- Лидер загружает текст воскресной проповеди.
- **Лидер сам создаёт посты**: выбирает, какой отрывок проповеди войдёт в сообщение на какой день (Пн–Вс), может добавить свою мысль.
- В выбранный день и время участникам приходит **push-уведомление**.
- Под сообщением — **реакции** и **комментарии**.

### 2. Анонимные вопросы лидерам
- Участник задаёт вопрос анонимно (проблема, переживание, искушение).
- Вопрос видят **все лидеры**, ответить может **любой лидер** (это же решает правило «взрослый не переписывается с подростком один на один»).
- Можно указать пожелание «хочу, чтобы ответил X» — но вопрос всё равно видят все лидеры.
- Лидеры видят список **вопросов без ответа**.
- Участник видит **имя** каждого лидера, который ему отвечает.
- **Полная анонимность — схема «секретный ключ на телефоне»** (утверждено):
  - при создании вопроса телефон генерирует случайный секретный код и хранит его только у себя (secure storage);
  - в базе вопрос лежит с отпечатком (хэшем) этого кода, **без имени и без аккаунта**;
  - запросы к анонимным вопросам идут **без токена входа** пользователя, чтобы сервер не мог связать их с аккаунтом;
  - телефон с кодом видит ответы лидеров; никто больше не знает, чей вопрос — даже владелец базы.
  - Цена: сменил телефон / удалил приложение — переписка пропала (можно задать новый вопрос).
  - Пуш «тебе ответили» не отправляем (он выдал бы телефон) — новый ответ видно значком при открытии приложения.
- **Автоудаление** переписки через **7 дней** после последнего сообщения + кнопка «Удалить сейчас».
- На экране вопросов — блок помощи: «Если тебе плохо или опасно прямо сейчас — 988 (звонок/SMS) или 911».
- Лидер может **закрыть** диалог (например, если пишут гадости).

### 3. Общий чат
- Сообщения, фото и видео, **реакции**, **пересылка** медиа.
- Отделён от ежедневного слова и от вопросов лидерам.

### 4. События и идеи
- **Календарь** предстоящих мероприятий, кнопка **«Приду»**, видно кто идёт.
- Раздел **идей** для будущих мероприятий: любой предлагает, остальные голосуют.

### 5. Фото и видео
- Лидеры публикуют **фотоотчёты и видео** для всей группы (альбомы).

### 6. Дни рождения
- Все видят «Сегодня день рождения у …».
- Лидеры видят ближайшие дни рождения и могут **поздравить** (личное поздравление + push).

## Возможности лидеров
- создавать и редактировать события;
- загружать проповеди, создавать ежедневные посты;
- загружать фото и видео;
- отвечать на анонимные вопросы, закрывать диалоги;
- видеть список участников (имена и роли);
- поздравлять с днём рождения;
- модерировать: удалять сообщения/комментарии, смотреть жалобы.

Только админ: назначать и снимать лидеров.

## Обязательные требования Apple / Google
- В чате и комментариях: **«Пожаловаться»** и **«Заблокировать пользователя»**; лидеры удаляют неприемлемое.
- **Удаление аккаунта** прямо в приложении.
- **Политика конфиденциальности** (страница + ссылка в магазине). Черновик на английском — `docs/privacy-policy.md`; перед публикацией заполнить поля в квадратных скобках и разместить на сайте.
- Google Play (новый личный аккаунт): перед публикацией 14 дней закрытого теста минимум с 12 тестировщиками.

## Карта экранов

**Вход**
- Приветствие → «Создать аккаунт» (имя, email) / «Войти» (email) → экран ввода кода из письма.

**Нижнее меню (5 вкладок)**
1. **Главная** — «Слово на сегодня» (отрывок + мысль лидера, реакции, «Обсудить»), дни рождения сегодня, личное поздравление, ближайшее событие с «Приду», посты этой недели, свежий фотоотчёт. Лидеру — быстрые действия (новый пост, событие, фотоотчёт, проповеди).
   - Пост дня → полный текст, реакции, комментарии.
2. **Чат** — общий чат: текст, фото/видео, реакции, переслать, пожаловаться, заблокировать, удалить (своё / лидер — любое).
3. **События** — переключатель «Календарь | Идеи».
   - Календарь: месяц с отметками, список событий, «Приду». Карточка события: описание, кто идёт. Лидер: создать/редактировать/удалить.
   - Идеи: список по голосам, «Предложить идею».
4. **Вопросы**
   - Участник: объяснение анонимности, «Задать вопрос», мои диалоги (статус, через сколько удалится), блок помощи 988/911.
   - Лидер: «Без ответа | Все», диалог с ответом, «Закрыть диалог».
5. **Профиль** — мои данные, фото и видео (альбомы), уведомления, конфиденциальность, заблокированные, удалить аккаунт, выйти.
   - Лидер: проповеди и посты, участники (список; админ — назначить лидером), дни рождения, жалобы.

**Экраны лидера**
- Проповеди → загрузить проповедь (название, проповедник, дата, текст) → проповедь разбита на абзацы → лидер отмечает абзацы → «Создать пост» (отрывок можно подправить, добавить мысль, выбрать день недели и время пуша) → план недели Пн–Вс.
- Новое событие, новый фотоотчёт, поздравление с днём рождения.

## Технический план
- Приложение: Expo + TypeScript, навигация — React Navigation (без expo-router, чтобы браузерная версия открывалась по любой ссылке).
- База данных и вход: **Supabase**: Postgres с правилами доступа (RLS), авторизация, хранилище фото/видео, realtime для чата.
  - Проект **Youth** в организации PaulCleanLLC (тариф Pro), идентификатор проекта `gtwhzifxvxyvffoayymh`. Отдельный проект — с другими проектами владельца не смешивается.
  - **NocoDB не используем** (решено 2026-11-19): в нём нет входа для участников, правил «кто что видит» и серверной проверки для анонимных вопросов. Таблицы при необходимости смотрим в редакторе самого Supabase.
  - Структура базы лежит в `supabase/migrations/`, тесты правил доступа и анонимности — `npm run test:db` (запускаются локально, без облака).
- Пуши: Expo Push + запуск по расписанию на сервере (Supabase cron + Edge Function).
- Анонимные вопросы — отдельные функции базы, доступные без входа, принимают секретный код и сверяют хэш.
- Ключи доступа хранить в отдельной облачной среде «youth» (не в Default), чтобы не смешивать с другими проектами.

## База: как она устроена
- Файлы: `supabase/migrations/…_core.sql` (таблицы, правила, функции) и `…_platform.sql` (расписание, «живые» обновления чата, хранилище файлов).
- Перед любым изменением базы: `npm run test:db` — тесты поднимают Postgres в памяти и проверяют, что чужой не может прочитать или изменить то, что ему нельзя. В настоящую базу изменения уходят командой `supabase db push`.
- **Главный лидер (админ)** назначается вручную владельцем базы: после регистрации его аккаунта — одной командой в панели Supabase. Из приложения сделать себя админом или лидером нельзя.
- Анонимные вопросы: сервер принимает их только БЕЗ входа в аккаунт и хранит лишь отпечаток секретного кода. Честная оговорка: как у любого сервера, в технических журналах Supabase на короткое время остаётся IP-адрес запроса — к аккаунту он не привязан.
- Фото и видео: закрытое хранилище `media`, сейчас лимит 50 МБ на файл (для длинных видео лимит нужно будет поднять в настройках проекта). Файл можно открыть только войдя в аккаунт; публичных ссылок нет. Проверено на живой базе: участник не может загрузить в чужую папку или в альбомы, гость не может ни скачать, ни получить ссылку.
- Настройки входа (длина кода 6 цифр, письмо с кодом) лежат в `supabase/config.toml` и `supabase/templates/code.html`. **Команду `supabase config push` не запускать:** она применяет весь файл целиком без подтверждения, а почтовых настроек (см. ниже) в файле нет — письма с кодом перестанут уходить. Настройки входа менять в панели Supabase.
- **Почта для кодов (подключено 2026-11-19):** сервис Resend, домен `woodmarkyouth.com` (куплен на Porkbun, оплачен до 2027-11-20), отправитель «Youth Group» <hello@woodmarkyouth.com>. Подключено вручную через SMTP в панели Supabase (Authentication → Emails → SMTP Settings); ключ Resend — «только отправка, только этот домен», лежит только в Supabase. Готовую кнопку «Connect to Supabase» не использовали намеренно: она просит доступ на запись ко всей организации, включая рабочие проекты. Лимит — 100 писем в час. В DNS домена добавлены 4 записи Resend (DKIM, две CNAME для отправки, DMARC).
- Аккаунт Resend общий с PaulClean и на бесплатном тарифе: 100 писем в день на оба проекта вместе. Перед запуском на всю группу перейти на платный тариф, иначе в день массовой регистрации могут встать и письма PaulClean.
- Встроенный советник безопасности Supabase показывает 15 предупреждений «функцию можно вызвать» — это ожидаемо: каждая такая функция внутри сама проверяет, кто её вызывает (и на это есть тесты). Ошибок нет.

## Два режима приложения
- **Настоящий** — когда в проекте есть файл `.env.local` с адресом и публичным ключом Supabase (образец — `.env.example`). Данные лежат в базе, вход по коду из письма. Файл `.env.local` в git не попадает; для сборки в магазины те же два значения задаются в настройках сборки Expo.
- **Демо** — когда файла `.env.local` нет. Данные выдуманные и живут в памяти, для входа подходит любой код из 6 цифр, во вкладке Me есть переключатель ролей (жёлтая рамка «Prototype only»). Нужен, чтобы править внешний вид, не трогая базу.
- Экраны в обоих режимах одни и те же. Общий список действий — `src/data/storeTypes.ts`, настоящий режим — `src/data/liveStore.tsx`, демо — `src/data/demoStore.tsx`.
- Обновления: чат, комментарии, реакции, «I'm in» и голоса за идеи появляются у всех сразу; остальное обновляется при открытии приложения и раз в 45 секунд.
- Весь внешний вид (цвета, шрифты, скругления) собран в одном месте — `src/theme.ts`; общие детали (кнопки, карточки) — в `src/components/ui.tsx`.
